# 02 方法流程

## 总流程

工程作品集驱动学习法的完整流程：

    真实项目
      ↓
    AI 辅助推进
      ↓
    限定阶段计划
      ↓
    工程调试与验证
      ↓
    文档复盘
      ↓
    问答验证理解
      ↓
    GitHub 作品集整理
      ↓
    面试 / 申请 / 职业转化

## 1. 真实项目

不从孤立知识点开始，而是从真实工程项目开始。

例如：

- 跑通 ROS2 / Nav2 基础链路
- 复现 TurtleBot3 导航 demo
- 调试导航参数
- 写评估脚本
- 整理 debug 文档

真实项目会自然暴露知识缺口。

## 2. AI 辅助推进

AI 用来辅助：

- 拆解任务
- 解释代码
- 提供命令
- 分析日志
- 生成文档初稿
- 准备面试问题

但 AI 不能无限发散，必须被阶段目标约束。

## 3. 限定阶段计划

每个阶段只解决一个明确问题。

例如：

- 今天只跑通 Nav2 demo
- 今天只理解 controller_server
- 今天只整理 Week1 summary
- 今天只准备 5 个面试问题

阶段计划的作用是防止学习过程失控。

## 4. 工程调试与验证

每个结论都需要有证据。

常见证据包括：

- 命令输出
- 日志
- 截图
- 参数对比
- 实验结果
- README 说明
- Git commit 记录

## 5. 文档复盘

每个阶段结束后，必须沉淀文档。

文档类型包括：

- daily log
- weekly summary
- debug report
- runbook
- project README
- interview Q&A

文档不是额外工作，而是学习过程的一部分。

## 6. 问答验证理解

学习完成后，需要用问答验证是否真正理解。

验证方式：

- AI 提问
- 自己回答
- 回答不出来就回到代码和文档
- 直到可以用自己的话讲清楚

目标不是“看懂”，而是“讲得出”。

## 7. GitHub 作品集整理

private repo 用于完整记录学习过程。

public repo 用于脱敏展示：

- 项目背景
- 技术路线
- 调试过程
- 实验结果
- 复盘总结
- 可复现步骤

## 8. 面试 / 申请 / 职业转化

最后把项目整理成可表达的能力证据。

面试时要能回答：

- 你做了什么？
- 为什么这么做？
- 遇到了什么问题？
- 怎么定位？
- 怎么验证？
- 最终结果是什么？
- 你从中学到了什么？
