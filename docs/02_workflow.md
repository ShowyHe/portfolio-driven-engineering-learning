# 02 执行流程

## 总流程

工程作品集驱动学习法的完整流程是：

    真实项目
      ↓
    AI 辅助推进
      ↓
    限定阶段计划
      ↓
    工程调试与验证
      ↓
    文档复盘
      ↓
    问答验证理解
      ↓
    GitHub 作品集整理
      ↓
    面试 / 申请 / 职业转化

## 1. 真实项目

学习不从孤立知识点开始，而是从真实工程项目开始。

真实项目会自然暴露知识缺口，例如：

- 环境无法启动
- 依赖安装失败
- 节点没有运行
- topic 没有数据
- 参数修改没有效果
- 代码逻辑看不懂
- 面试时无法讲清楚

这些问题会倒逼学习者真正理解系统。

## 2. AI 辅助推进

AI 在这个方法中不是替代学习者，而是作为工程学习助手。

主要作用包括：

- 拆解任务
- 解释概念
- 分析日志
- 生成命令
- 阅读代码
- 整理文档
- 设计面试问题

但 AI 辅助必须被目标约束，否则容易发散。

## 3. 限定阶段计划

每个阶段只解决一个明确问题。

例如：

- 今天只完成环境安装
- 今天只跑通一个 demo
- 今天只理解一个节点
- 今天只修改两个参数做对照
- 今天只写一篇 debug report
- 今天只整理一组面试问答

阶段计划的作用，是让学习过程保持可控。

## 4. 工程调试与验证

工程学习不能只停留在“理解概念”。

每个结论都需要证据支撑。

常见证据包括：

- 命令输出
- 日志
- 截图
- 参数对比
- 实验结果
- Git commit
- README 说明

## 5. 文档复盘

每个阶段结束后，需要把过程写成文档。

常见文档包括：

- daily log
- weekly summary
- debug report
- runbook
- project README
- interview Q&A

文档不是额外工作，而是学习闭环的一部分。

## 6. 问答验证理解

真正理解不是“看过”，而是能用自己的话讲出来。

验证方式：

1. AI 提问
2. 自己回答
3. 回答不出来就回到代码、命令和文档
4. 再次复述
5. 直到可以清楚表达

## 7. GitHub 作品集整理

private repo 用于完整记录学习过程。

public repo 用于脱敏展示成果，包括：

- 项目背景
- 技术路线
- 调试过程
- 实验结果
- 总结复盘
- 可复现步骤

## 8. 面试 / 申请 / 职业转化

最后把学习成果转化为可表达的能力证据。

每个项目都要能回答：

- 我做了什么？
- 为什么这么做？
- 遇到了什么问题？
- 如何定位问题？
- 如何验证结果？
- 最终产出是什么？
- 我从中学到了什么？

## 流程总结

这套方法的本质，是让学习不再停留在输入，而是持续产出工程证据。
