# 04 案例：从工程学习到求职转化

## 背景

这个案例记录我如何把 2026 年 1 月到 3 月初的 ROS2 / Nav2 工程学习成果，转化为求职面试材料和机器人软件工程能力证据链。

## 时间线

| 时间 | 阶段 | 内容 |
|---|---|---|
| 2026-01-04 到 2026-01-11 | 基础链路跑通 | 安装 ROS2，跑通 TurtleBot3 / Nav2 demo |
| 2026-01 中旬到 2026-02 底 | 工程作品集建设 | Nav2 实验、参数对照、评估脚本、runbook、debug 文档、周总结 |
| 2026-03 初到 2026-03-12 | 面试转化 | 整理简历、项目表达、面试问答、GitHub 证据链 |
| 2026-03-12 后 | 真实工程验证 | 进入机器人公司，参与真实机器人项目调试与开发 |

## 转化方式

学习成果不是停留在笔记里，而是进一步整理成：

- GitHub 项目 README
- 调试文档
- 实验记录
- 面试问答
- 项目经历描述
- 简历中的工程证据

## 面试表达结构

每个项目都按照以下结构准备：

1. 项目背景是什么
2. 我负责什么
3. 遇到了什么问题
4. 如何定位问题
5. 如何验证结果
6. 最终产出是什么
7. 我从中学到了什么

## 方法价值

工程作品集驱动学习法的关键价值，是把学习过程变成可以被验证的能力证据。

不是只说“我学过 ROS2 / Nav2”，而是可以展示：

- 我跑通过什么系统
- 我调试过什么问题
- 我写过什么文档
- 我做过什么实验
- 我如何复盘问题
- 我如何把项目讲清楚
